Project overview

Recognizing a handwritten digit.

This project trains a neural network to recognize drawings of digits from 0 to 9. The website shows its predictions, saved training progress, and the calculations inside the network. The next goal is to run those prediction calculations on an FPGA.

What happens to a drawing?

  1. A drawing is cropped, centered, and resized to a 16 × 16 image.
  2. Its 256 pixels become numbers passed into the neural network.
  3. The network combines those numbers using weights learned during training.
  4. It produces a score for each digit and selects the highest one.

Visitors can draw a digit in the Explorer or choose a saved drawing. New drawings are processed in the browser and do not retrain the model.

What works now?

The project includes a drawing collector, image processing, models written in Python with NumPy, and this interactive website.

The dataset contains 100 original drawings from one writer. Eighty were used for training and 20 were held back for validation.

The final neural network correctly classified 18 of the 20 validation drawings. Training replay uses 11 saved checkpoints with actual model weights.

The website also supports drawing input, neuron inspection, training charts, and phone navigation.

Why test integer calculations?

The original model uses floating-point numbers, which can store values with fractional parts. The project also tests fixed-point numbers: integers with a scale that represents fractional values.

This helps determine how much precision the model needs before building its calculations in hardware.

The tested 12-bit format made the same predictions as the original model on all 100 collected drawings. That means the predictions matched, not that every drawing was classified correctly.

The integer code was checked against a separate calculation in 150 generated test cases.

What is an FPGA?

An FPGA is a chip that can be configured to implement digital circuits. Instead of only writing instructions for a processor, a hardware design defines how calculations and data move through the circuit.

The goal is to build the network's prediction calculations in hardware, compare its outputs with Python, and measure its speed and hardware use. Training will remain separate in Python.

A single hardware neuron has been written in SystemVerilog and tested in simulation. All 416 test cases matched the Python reference outputs and clipping flags. Checks also covered reset, pauses between inputs, and the completion signal.

View the recorded neuron simulation. This short example shows inputs, accumulated values, and output timing, both with and without ReLU.

The complete network has not been implemented in hardware or run on a physical FPGA. The public Explorer performs predictions in the browser.

What comes next?

  • Expand the design to a layer and then the complete network.
  • Compare hardware outputs with the Python integer model.
  • Collect handwriting from more people and test on new writers.
  • Measure hardware timing, accuracy, and resource use.
