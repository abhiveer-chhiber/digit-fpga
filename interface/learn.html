Project overview

Recognizing a handwritten digit.

This project trains a neural network to recognize drawings of digits from 0 to 9. The website shows its predictions, saved training progress, and the calculations inside the network. The next goal is to run those prediction calculations on an FPGA.

What happens to a drawing?

  1. A drawing is cropped, centered, and resized to a 16 × 16 image.
  2. Its 256 pixels become numbers passed into the neural network.
  3. The network combines those numbers using weights learned during training.
  4. It produces a score for each digit and selects the highest one.

Visitors can draw a digit in the Explorer or choose a saved drawing. New drawings are processed in the browser and do not retrain the model.

What works now?

The project includes a drawing collector, image processing, models written in Python with NumPy, and this interactive website.

The dataset contains 100 original drawings from one writer. Eighty were used for training and 20 were held back for validation.

The final neural network correctly classified 18 of the 20 validation drawings. Training replay uses 11 saved checkpoints with actual model weights.

The website also supports drawing input, neuron inspection, training charts, and phone navigation.

Why test integer calculations?

The original model uses floating-point numbers, which can store values with fractional parts. The project also tests fixed-point numbers: integers with a scale that represents fractional values.

This helps determine how much precision the model needs before building its calculations in hardware.

The tested 12-bit format made the same predictions as the original model on all 100 collected drawings. That means the predictions matched, not that every drawing was classified correctly.

The integer code was checked against a separate calculation in 150 generated test cases.

What is an FPGA?

An FPGA is a chip that can be configured to implement digital circuits. Instead of only writing instructions for a processor, a hardware design defines how calculations and data move through the circuit.

The goal is to build the network's prediction calculations in hardware, compare its outputs with Python, and measure its speed and hardware use. Training will remain separate in Python.

A single hardware neuron has been written in SystemVerilog and tested in simulation. All 416 test cases matched the Python reference outputs and clipping flags. Checks also covered reset, pauses between inputs, and the completion signal.

View the recorded neuron simulation. This short example shows inputs, accumulated values, and output timing, both with and without ReLU.

The complete network has not been implemented in hardware or run on a physical FPGA. The public Explorer performs predictions in the browser.

What comes next?

  • Expand the design to a layer and then the complete network.
  • Compare hardware outputs with the Python integer model.
  • Collect handwriting from more people and test on new writers.
  • Measure hardware timing, accuracy, and resource use.

Project scope

From a learned model
to FPGA inference.

This project investigates how a handwritten digit classifier can move from a Python model into digital hardware. I use a custom dataset, compare model and number formats, and check hardware calculations against a software reference.

The software implementation includes a collection interface, image preprocessing, linear baselines, a NumPy neural network, fixed-point inference, and an interactive browser viewer.

A single neuron is also implemented in SystemVerilog. Its outputs and saturation flags matched the Python reference in all 416 simulation cases. The testbench also checks reset, input gaps, saved bias and ReLU settings, and control-signal behavior.

The complete neural network has not yet been implemented in RTL, synthesized, or run on a physical FPGA. The public Explorer performs predictions in the browser, using the exported software model. FPGA timing and resource use have not been measured.

From drawing to prediction

Method and implementation.

01 / DATA

Source images.

Original drawings were collected at 128×128. Both experimental resolutions were generated from the same source images. This controls for differences in handwriting when comparing resolution.

original: 128 × 128
experiment A: 8 × 8 = 64 inputs
experiment B: 16 × 16 = 256 inputs

Writer identifiers support future evaluation with writers excluded from training. The current dataset contains 100 drawings from one writer.

02 / PREPROCESSING

Cropping, padding, and normalization.

The script crops unused space and places the drawing in a padded square. It preserves proportions, so a narrow 1 does not become a wide rectangle. BOX resizing averages ink intensity instead of forcing pixels to black or white.

pixels = np.asarray(image, dtype=np.float32) / 255.0

Dividing by 255 changes the pixel range to 0–1. It does not change the handwriting or tell the model which digit it is.

03 / VALIDATION

Fixed validation split.

A fixed split assigns 80 drawings to training and 20 to validation. Both resolutions use identical assignments. Validation labels are excluded from parameter updates during training.

Validation supports model comparison but does not constitute an untouched final test set. With 20 validation samples, one prediction changes accuracy by five percentage points.

04 / FORWARD PASS

Weighted sums and ReLU.

Each neuron multiplies its inputs by weights, adds them together, and adds a bias. Hidden layers then use ReLU, which replaces negative values with zero.

values = activations[-1] @ weights + bias
values = np.maximum(values, 0)

Without a nonlinear activation between layers, stacking linear layers would still describe a linear transformation. ReLU lets the network represent more complex relationships.

05 / LEARNING

Backpropagation and Adam.

Cross-entropy measures how much probability the model gives the correct label. Backpropagation uses the chain rule to find how each parameter affects that loss.

delta = probabilities - targets
weight_gradient = previous_activations.T @ delta

Training averages gradients across a batch and adds L2 regularization. Adam uses moving averages of gradients and squared gradients to choose parameter updates. It does not replace backpropagation.

Analytical gradients were checked against numerical estimates on a small test network before training. The largest absolute difference was approximately 1.33e-11.

Integer inference

Fixed-point results.

The final neural network checkpoint was also evaluated using integer calculations. All four formats cover about −32 to 32 and use 32-bit accumulators. The comparison changes fractional precision.

Checkpoint 1000 · 80 training and 20 validation drawings
Storage / fractional bits Training correct Validation correct Validation agreement with float Maximum validation score error Saturation events

The 16-bit and 12-bit formats preserved the original predictions on all 100 drawings. The 10-bit format corrected one validation prediction. One changed prediction does not establish better performance on other handwriting.

With two fractional bits, the 8-bit format rounded 32,703 of 32,768 first-layer weights to zero. Accuracy dropped without saturation. This result applies to the tested scale, not every 8-bit model.

Agreement counts predictions matching the floating-point model. Score error compares output values after converting integers back to the original scale. Saturation events include both data splits.

The integer implementation matched a separate scalar reference in 150 generated test cases, including 66 with accumulator saturation.
